# Medication timing rules — sources, assumptions, review status

**None of these rules has been reviewed by a pharmacist or doctor.** Passing tests proves
the engine applies the rule file correctly; it does not prove a rule is clinically right
or sufficient. Do not use with real patients until a qualified person has signed off
(set `"reviewed": true` per rule only after that).

## Where the rules come from

`backend/safety_rules.json`. Each rule is a **transcription of one sentence** from a US FDA
drug label (via openFDA / DailyMed), with the label's `set_id`, effective date, section and the
exact quote. No rule was written from memory or generated by a model.

`python backend/tools/verify_rule_sources.py` re-fetches every label and confirms each
quote still appears word for word. Last run: **25 sources, 0 failures** (2026-10-04).
A failure means the label changed → a person must re-read that rule.

## What the engine does and refuses (`backend/safety_engine.py`)

* Spacing: two real doses closer than a rule's minimum are a **conflict**. Rules can be
  asymmetric (ciprofloxacin: 2 h *before* or 6 h *after* calcium/iron/antacids/zinc).
* A **late** dose counts at the time it was actually taken.
* **Proposals** only ever move the *later* dose *later*, to the earliest allowed time, and only
  if that stays before the medicine's own next dose, doesn't touch a taken dose, isn't a
  high-risk medicine, and creates no new conflict. The server re-derives the answer when the
  patient accepts; the client's time is never trusted. The original time stays in the audit log.
* **Labels that say "separate" but give no time** (doxycycline + calcium/iron/antacids;
  levothyroxine + acid reducers) → "needs clarification", no invented interval.
* **No rule for a pair** (e.g. iron + calcium) → nothing is claimed, and the UI says unlisted
  pairs have *not* been shown safe. The NIH Office of Dietary Supplements pages that might
  answer iron/calcium blocked automated access (HTTP 403), so no interval was added.
* **Missed dose:** only ciprofloxacin has a number the label gives (take it unless fewer than
  6 h remain before the next dose); metformin's label says skip and continue; others show the
  label sentence only. **High-risk medicines** (warfarin, insulin, DOACs, heparin, clopidogrel
  etc., digoxin, methotrexate) never get a computed catch-up time.
* Never doubles a dose, never shortens a gap, never changes the prescribed dose/frequency/duration.

## Known limits and assumptions to review

1. **US labels, Indian products.** Ingredient-level rules are applied to Indian brands via an
   alias table (`ingredient_aliases`). Indian labels can differ. The UI always says "US FDA label".
2. Alias matching is by name only (e.g. "Shelcal" = calcium). A combination product whose name
   hides an ingredient will not be matched.
3. One label per ingredient was used (the first current, complete one found). Labels of
   different manufacturers can word things differently.
4. "Apart" for levothyroxine is read as symmetric (4 h before *or* after) per the label sentence.
5. Alendronate's missed-dose text is the *once-weekly* regimen.
6. The conflict window is ±48 h around "now"; repeating patterns beyond that are not simulated.
7. Windows are in the patient's local time; a time-zone change mid-course shifts future
   reminders but does not rewrite doses already generated.
8. Pharmacist review is also needed for: the high-risk list, the 6-hour ciprofloxacin reading,
   and the wording shown to patients.

## Adding or changing a rule

1. Find the sentence in a current official label (DailyMed / openFDA). Copy it exactly.
2. Add the rule to `safety_rules.json` with `set_id`, `effective`, `section`, `quote`, `reviewed:false`.
3. `python backend/tools/verify_rule_sources.py` must pass.
4. Add a test in `backend/tests/test_safety_engine.py` for the new numbers.
5. Have a pharmacist review it; only then set `reviewed:true`.

| openFDA enforcement | US recalls (ongoing) | Batch-specific; openFDA says not to use it for public alerts. |
| Drugs@CDSCO (approved drugs) | India approval | **No public data feed** — shown as "verification pending" with a link, never guessed. |

Not implemented: CDSCO "Not of Standard Quality" monthly alert PDFs, EMA, state licensing.
